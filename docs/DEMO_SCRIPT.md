## แผนสำรอง
| ถ้า... | ทำ |
|---|---|
| CiRA ค้าง/เปิดไม่ได้ | เปิด terminal ใหม่ `npm run sim` → ข้อมูลเหมือน CiRA ทุกประการ (ไฟ CiRA จะขึ้น `SIM`) พูดว่า "ใช้ simulator ที่ส่ง payload เหมือนกันเพื่อสาธิต pipeline" |
| Mosquitto ไม่ขึ้น / port 1883 ถูกใช้ | `npm run broker:node` |
| ไม่มีเน็ต / Atlas ล่ม | `npm run bridge:nodb` + `npm run sim` → โชว์การนับใน terminal; อธิบายว่า bridge มีคิวเขียนซ้ำเมื่อเน็ตกลับ |
| Dashboard Vercel ช้า | ใช้ `localhost:3000` แทน |
| ทุกอย่างพัง | เปิดวิดีโอที่อัดหน้าจอไว้ล่วงหน้า (อัดไว้ด้วย!) |

## คำถามที่อาจารย์น่าจะถาม
**Q: ทำไมไม่ให้ CiRA เขียนลง database ตรง ๆ?**
A: CiRA ส่งผลทุกเฟรม (~15 ครั้ง/วินาที) กล่องเดียวจะถูกบันทึก 40 ครั้ง ต้องมีตัวกลางนับครั้งเดียวและตัดสินผลด้วยการโหวต อีกทั้ง MQTT ทำให้เพิ่มอุปกรณ์อื่นมารับข้อมูลได้โดยไม่แก้ CiRA

**Q: นับซ้ำได้ไหมถ้าโมเดลจับกล่องหลุดไปแล้วกลับมา?**
A: tracker จำกล่องไว้ `TRACK_TTL_MS` (1 วินาที) และทำนายตำแหน่งจากความเร็ว ถ้าหลุดนานกว่านั้นแล้วเกิด track ใหม่ *หลัง* เส้นนับ ก็จะไม่ถูกนับซ้ำ เพราะนับเฉพาะ track ที่เริ่มก่อนเส้นแล้วข้ามไป มี unit test ครอบคลุม

**Q: ถ้าโมเดลทายผิด?**
A: ตัดสินจากหลายสิบเฟรม ไม่ใช่เฟรมเดียว และถ้า ≥30% ของเฟรมบอกว่าเสีย จะ FAIL ทันที (bias to FAIL) เพราะปล่อยกล่องเสียผ่านแพงกว่า

**Q: Edge AI ต่างจาก Cloud AI ยังไง?**
A: ประมวลผลภาพที่เครื่องข้างสายพาน ส่งแค่ผลลัพธ์ไม่กี่ร้อย byte ขึ้น cloud → latency ต่ำ, ใช้เน็ตน้อย, ภาพไม่ออกนอกโรงงาน, ยังตรวจได้แม้เน็ตหลุด

**Q: QoS ของ MQTT ใช้ระดับไหน?**
A: detections ใช้ QoS 0 เพราะเป็นข้อมูลถี่ หายบางเฟรมไม่เป็นไร (tracker ทนได้) — ส่วนที่สำคัญคือ event ซึ่งเขียน DB โดยมี retry + unique `eventId`

**Q: ความปลอดภัย?**
A: Demo ใช้ broker แบบ anonymous ในวงแลนเท่านั้น ของจริงต้องเปิด username/password + TLS (port 8883), ซ่อน `MONGODB_URI` ไว้ฝั่ง server (ไม่ใช้ `NEXT_PUBLIC_`), จำกัด IP ใน Atlas, `/api/reset` ต้องมี `ADMIN_TOKEN`

**Q: รองรับกี่กล่องต่อนาที?**
A: ขึ้นกับ fps ของ CiRA และความเร็วสายพาน; bridge ประมวลผลเฟรมได้หลักพันเฟรม/วินาที คอขวดคือโมเดล ดูค่า throughput บน dashboard ได้

**Q: total = good + damaged รับประกันได้อย่างไร?**
A: 1 document = 1 กล่อง และ `result` เป็นได้แค่ `PASS` หรือ `FAIL` ไม่มีสถานะอื่น; API ตรวจซ้ำทุกครั้ง (`invariantOk`) และแสดง ✔ บนการ์ด
